Reflection: Cloud Computing in Daily Life and Version Control
1. Cloud Services I Use Regularly
   
It's actually crazy to realize how much our daily routine relies on cloud computing. From listening to music while studying to binge watching shows or catching up on group projects, almost everything we use sits on remote data centers. Three cloud apps I open practically every day are Spotify for music, Netflix for streaming, and Messenger to stay connected with friends and family.
   
  2.Identifying Service and Deployment Models
   
These platforms run on different setup frameworks depending on how they handle performance and data security:

-Spotify SaaS  Public Cloud It functions as Software as a Service (SaaS) on a Public Cloud. I just use the app to stream songs without worrying about server maintenance or how the audio files are stored. The underlying servers and algorithms are all managed on shared, public cloud infrastructure.

-Netflix SaaS  Public Cloud Just like Spotify, Netflix is a SaaS app running on a Public Cloud. It delivers high-definition video straight to my screen while using scalable cloud systems behind the scenes to handle massive global traffic without crashing.

-Facebook Messenger SaaS  Hybrid Cloud Messenger acts as SaaS, but it uses a Hybrid Cloud setup. It relies on public networks so messages send fast worldwide, but keeps sensitive stuff like encrypted chats, user credentials, and core data stored safely in private, proprietary data centers.

3. Git & GitHub for Cloud Projects
   
When building cloud systems, even a tiny typo in a configuration file can easily crash a live project. That’s why tools like Git and GitHub are a lifesaver for developers.

Git basically acts as a safety net. It tracks every single change you make, so if an update breaks the production environment, you can easily roll back to the last working version without panicking. Meanwhile, GitHub serves as the team’s workspace. It lets everyone work on their own features using branches so nobody accidentally overwrites each other's code. Through pull requests and code reviews, teams can catch bugs or security issues together before any changes actually hit the live cloud.
